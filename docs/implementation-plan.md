## 当前可以执行的操作

1. 在根目录运行 `.\.venv\Scripts\python.exe -m emotional_robot.cli serve`，启动已安装依赖的本地演示后端。
2. 打开 `http://127.0.0.1:8000/docs`，用演示口令授权，创建对话并发送“请叫我小周”。
3. 稍后在 `GET /v1/memories` 查看来源记忆，新建对话后问“我叫什么”。
4. 在记忆详情获取 revision，再 PATCH 纠正；使用旧 revision 再次修改应得到 409。
5. DELETE 记忆并查询删除任务，确认列表、导出和后续回复都不再使用该内容。
6. 在 `.env` 中填写自己的 DeepSeek Key 并切换 provider，重启后测试真实对话。模型抽取结果在管理页确认。
7. 在 DevEco Studio 打开 `apps/harmony`，安装 7.0 SDK，生成自己的签名后连接手机。具体见[客户端运行指引](../apps/harmony/README.md)。

## 当前实现边界

所有 API 使用服务端从 Bearer 口令推导的用户身份。角色记忆默认独立，目前只实现角色级作用域，跨角色显式共享留到后续。角色默认 ID 为 `companion`。

记忆生命周期已实现 active、candidate、superseded、deleted，过期按 expires_at 排除召回。版本记录支持查看修改历史；完整的事实有效时间、历史状态推理、多实体关系图尚未实现。

正文删除和任务屏障在当前数据库中生效。没有实现外部索引、第三方引擎、备份恢复和离线客户端缓存，因此不能将当前删除状态解释为全设备、全备份清除完成。

目前客户端联网读取后端持久化会话；不缓存聊天正文，避免未实现删除同步时留下额外副本。端侧离线会话、加密数据库和密钥持久化单列后续任务。

数据库首次启动使用 SQLAlchemy 建表，尚无既有生产数据迁移链。首次正式部署前须补充数据库迁移、备份恢复和 TLS 部署，不直接把开发数据库当作已完成生产验收的系统。
